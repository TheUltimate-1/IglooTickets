## 1. 🛡️ Security, Cryptography & Database Hardening

### A. PostgreSQL Stored Procedure for Check-In (RPC)
* **Current State**: Check-in executes via client-side Supabase `.update().eq('id', ticket.id).eq('status', 'VALID')`. While race-condition safe, the Supabase anon role currently has permission to update the table directly.
* **Improvement**: Encapsulate the entire validation and check-in flow in an atomic `SECURITY DEFINER` function in PostgreSQL:
  ```sql
  CREATE OR REPLACE FUNCTION check_in_ticket_rpc(
      p_event_id UUID,
      p_token TEXT,
      p_gate TEXT,
      p_scanner_user TEXT
  )
  RETURNS JSONB
  LANGUAGE plpgsql
  SECURITY DEFINER
  AS $$
  DECLARE
      v_ticket RECORD;
      v_updated RECORD;
  BEGIN
      -- 1. Find ticket
      SELECT * INTO v_ticket FROM tickets 
      WHERE event_id = p_event_id AND token = p_token;
      
      IF NOT FOUND THEN
          RETURN jsonb_build_object('success', false, 'reason', 'NOT_FOUND');
      END IF;
      
      -- 2. Check if already checked in
      IF v_ticket.status = 'CHECKED_IN' THEN
          RETURN jsonb_build_object(
              'success', false, 
              'reason', 'DUPLICATE',
              'attendee_name', v_ticket.attendee_name,
              'tier', v_ticket.tier,
              'checked_in_at', v_ticket.checked_in_at,
              'checked_in_gate', v_ticket.checked_in_gate
          );
      END IF;
      
      -- 3. Atomic check-in
      UPDATE tickets
      SET status = 'CHECKED_IN',
          checked_in_at = NOW(),
          checked_in_gate = p_gate,
          checked_in_by = p_scanner_user
      WHERE id = v_ticket.id AND status = 'VALID'
      RETURNING * INTO v_updated;
      
      -- 4. Audit Log
      INSERT INTO audit_logs (event_id, ticket_id, action, gate_name, scanner_username, attendee_name, result)
      VALUES (p_event_id, v_ticket.id, 'SCAN', p_gate, p_scanner_user, v_ticket.attendee_name, 'SUCCESS');
      
      RETURN jsonb_build_object(
          'success', true,
          'attendee_name', v_ticket.attendee_name,
          'tier', v_ticket.tier,
          'ticket_number', v_ticket.ticket_number
      );
  END;
  $$;
  ```
* **Benefit**: We can revoke all direct `UPDATE` permissions from public/anon users on `tickets`. Clients can only invoke `supabase.rpc('check_in_ticket_rpc', ...)`, eliminating any possibility of unauthorized table modifications.

### B. Cryptographically Signed QR Codes (HMAC-SHA256)
* **Current State**: QR codes embed UUID tokens.
* **Improvement**: Generate QR payloads formatted as:
  `TOKEN.HMAC_SIGNATURE` (where signature is `HMAC-SHA256(TOKEN + EVENT_ID, EVENT_SECRET)`).
* **Benefit**:
  * Offline scanners can cryptographically prove the QR code was generated by the event organizer before even querying the database.
  * Completely prevents forged or guessed QR codes.

### C. Rate Limiting on Gate PIN & Manual Searches
* Add progressive client-side cooldowns (1s, 3s, 10s) on repeated failed manual token lookups or incorrect gate PIN attempts to prevent brute-force probing.

## 2. 📱 Gate Scanner & Venue Field Operations

### A. Progressive Web App (PWA) & Offline Asset Caching
* **Implementation**:
  * Add `manifest.json` with app icons, theme color, and `"display": "standalone"`.
  * Add Service Worker (`sw.js`) utilizing Cache-First strategy for CDN assets (Tailwind, FontAwesome, jsQR, sounds).
* **Benefit**:
  * Staff can "Add to Home Screen" on iOS & Android for a fullscreen native app experience without browser navigation bars.
  * Instant app boot even with 0% cellular signal inside thick concrete venues or basements.

### B. Offline Roster Pre-Cache & Background Sync (`IndexedDB`)
* **Problem**: Large festivals and concerts frequently suffer cellular network collapse when thousands of attendees gather.
* **Solution**:
  1. Before gates open, the scanner downloads a compressed roster of valid tokens for the active event into browser `IndexedDB`.
  2. If online: Verify via Supabase Realtime API.
  3. If offline: Instantly validate against the local `IndexedDB` copy and record check-in with a local timestamp.
  4. Once internet connection returns: Automatically replay and sync queued check-ins to Supabase using `navigator.onLine` and `window.addEventListener('online')`.

### C. Rapid Hands-Free Continuous Scanning Mode
* **Feature**: A toggleable "Burst / Rush Hour Mode":
  * Auto-dismisses the green "ACCEPTED" overlay after 1.0 second.
  * Immediately re-arms the camera without requiring the operator to touch the screen.
  * Enables sustained throughput of 30–40 check-ins per minute per turnstile lane.

### D. Bluetooth / USB Hardware Barcode Scanner Support (HID Wedge)
* **Feature**: Listen for rapid keystrokes (`keydown` events terminating in `Enter`).
* **Benefit**:
  * Gate staff can plug in or pair handheld laser barcode scanners (e.g. Zebra, Honeywell, Netum).
  * Laser scanning decodes in 50 milliseconds even on crinkled, wet, or phone-screen QR codes in direct sunlight.

### E. Pass-Out & Re-Entry Mode ("Scan-Out / Scan-In")
* **Problem**: Attendees leaving the venue to visit food trucks or parking lots need re-entry passes without letting pass-sharing occur.
* **Solution**:
  * Scanner UI has an **"Exit Mode" (Pass-Out)** switch.
  * Scanning an attendee marks them as `CHECKED_OUT` (with timestamp).
  * Scanning them upon return validates their re-entry and flips them back to `CHECKED_IN`.
  * Attempting to enter with a ticket that is already `CHECKED_IN` without a matching check-out triggers a duplicate alert.

### F. High-Contrast Daylight Mode (Anti-Glare)
* **Problem**: Dark glassmorphism interfaces are sleek indoors, but hard to read in direct sunlight at outdoor festival gates.
* **Solution**: Quick toggle for an ultra-high-contrast theme (pure white background, bold black typography, high-saturation red/green status cards).

### G. Camera Zoom & Torch Quick Toggle
* Add a zoom slider for modern smartphones using `MediaStreamTrack.applyConstraints({ advanced: [{ zoom: 2.0 }] })` to scan passes from a distance without crowding attendees.
* Gesture shortcut: Double-tap viewfinder to toggle torch / flashlight.

## 3. 🎟️ Ticketing Agent & Attendee Experience

### A. Automated Email Dispatch with Calendar Invites (`.ics`)
* Trigger Supabase Database Webhook &rarr; Edge Function / Resend API when a ticket is created with an email address:
  * Attached vector PDF ticket.
  * Embedded mobile-friendly QR pass image.
  * Standard `.ics` iCalendar file for 1-click addition to Apple Calendar & Google Calendar.

### B. Apple Wallet (`.pkpass`) & Google Wallet Integration
* Allow attendees to add their ticket directly to Apple Wallet or Google Pay:
  * Pops up on the attendee's phone lock screen when they arrive at the venue using GPS geofencing.
  * Works with zero screen unlock friction at the gate.

### C. Flexible Badge & Ticket Format Designer
* Expand the PDF generator beyond the current landscape stub (200x90mm):
  * **Conference Lanyard Badge (A6 / 4x6")**: Bold attendee name, organization/title, attendee tier badge (Speaker, VIP, Press), and rear agenda.
  * **Multi-Ticket A4 Sheets**: Print 4 or 6 tickets per sheet for physical batch box-office distribution.
  * Custom branding upload (event logo, sponsor logos, custom terms & conditions).

### D. Attendee Self-Service Portal & Transfers
* Public URL (`/ticket-view.html?token=...`) where attendees can:
  * View their live ticket status and event schedule.
  * Download their pass anytime.
  * Initiate a verified ticket transfer to another person (regenerating a new secure token and invalidating the old one).

### E. Seat, Table & Dietary Meta Fields
* Configurable custom fields during ticket issuance (e.g. Table Number, VIP Booth, Dietary Requirements, T-shirt size) displayed on the scanner screen upon check-in.

## 4. 📊 Analytics, Management & Multi-Day Access

### A. Real-Time Gate Velocity & Bottleneck Monitoring
* Live line chart showing check-ins per 5-minute window broken down by gate (*Gate 1*, *Gate 2*, *VIP Lane*).
* Alerts event supervisors if a gate exceeds capacity or falls behind expected throughput.

### B. Multi-Day Festival & Multi-Session Badges
* Schema enhancement to support multi-day access:
  * Store day-specific check-in flags (`day_1_checked_in_at`, `day_2_checked_in_at`).
  * Tier-based access gates (e.g., ticket is valid for general admission, but scanner at "VIP Backstage" displays `ACCESS_DENIED: TIER_MISMATCH`).

### C. Live Attendance Capacity Headcount Meter
* Real-time speedometer showing current venue occupancy:
  `Inside Venue = (Total Check-Ins) - (Total Check-Outs)` against venue fire code maximum capacity.

### D. Event Duplication & Archive
* **1-Click Clone**: Quickly duplicate recurring events (tier configurations, gates, staff assignments) for next week's or next year's event.
* **Archive Mode**: Retain historical ticket records for reporting while hiding past events from active scanner views.
